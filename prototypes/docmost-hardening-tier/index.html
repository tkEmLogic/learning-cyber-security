Boundary

The release workstation authorizes firmware. The OTA service distributes bytes. MCUboot verifies the image.

Stop conditions

  • The signing key is in Git.
  • The signing key is on the OTA service.
  • The unsigned image still boots.

Mentor prompts

Show, explain, diagnose, and plan. Record notes, not a score.

Incident: A valid HTTPS OTA service was compromised. It served an unsigned image that forced the beacon into the fast-blink error state. The device ran it.

Make the same attack fail

Phase 1: Reproduce

./course tier start 3
./course attack unsigned-image
./course device update --release attack-unsigned

Capture the valid TLS session, downloaded image, boot log, and LED behavior.

Phase 2: Investigate

  1. Who authenticated the connection?
  2. Who authorized the firmware?
  3. Why can trusted TLS carry hostile bytes?
  4. Which secret must never exist on the OTA service?

Phase 3: Harden

./course keys create firmware-release
./course harden signed-images
./course build
./course release publish tier-3-signed

Boot the approved release. Confirm that the OTA service does not have the private signing key.

Phase 4: Replay the incident

./course device update --release attack-unsigned
./course verify tier-3

The hostile image must fail. Then try modified, wrong-key, and truncated images.
