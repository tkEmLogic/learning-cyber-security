Course manifest and command workflow

This demo lets a Learner drive the proposed course.yml and ./course state model without installing tools or changing a repository.

Question: Does a worktree-first command workflow, backed by manifest capabilities and a local verification receipt, make setup, Tier 0, and the move to Tier 1 clear and safe? Try the refusal and cleanup cases as well as the successful path.

Assumption under test: tier start creates a new Course workspace from a published checkpoint. The Learner then runs short commands inside that worktree. A passing verify writes an untracked local completion receipt that unlocks the next tier.

          Where later commands run
          Run from the shared repository and pass --workspace every time.
          Enter the generated Course workspace and run short commands there.
          B. It keeps commands readable and lets Git identify the current tier and branch.
        

        

          How Tier 1 is unlocked
          Infer completion from branch names, commits, or evidence files.
          Write a local receipt only after manifest-declared verification passes.
          B. It is explicit and reproducible. The receipt is untracked and tied to the checkpoint plus Git revision.
        

        

          What Tier 1 starts from
          Continue from the Learner's Tier 0 branch.
          Create a fresh worktree from the published Tier 0 completion checkpoint.
          B. It gives every Learner the same starting state and preserves Tier 0 work separately.
        

        

          How a compose runtime is chosen
          Silently use the first runtime found.
          Use saved configuration, otherwise accept one detected runtime and refuse an ambiguous or missing choice.
          B. The selected mechanism stays visible.
